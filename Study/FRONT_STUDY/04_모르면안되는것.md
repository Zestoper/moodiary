# 프론트엔드 모르면 안 되는 것 — Moodiary 기준

---

## 1. SPA (Single Page Application) vs MPA

| | SPA | MPA |
|---|---|---|
| 페이지 이동 | JS로 컴포넌트 교체 | 서버에서 HTML 새로 받음 |
| 초기 로드 | 느림 (JS 번들 전체 다운) | 빠름 |
| 이후 이동 | 빠름 (새로고침 없음) | 느림 |
| 예시 | React, Vue, Angular | 전통적인 웹사이트 |

이 프로젝트는 React SPA입니다. `React Router`로 `/diary`, `/chat`, `/calendar` 등 URL이 바뀌어도 실제 서버 요청 없이 컴포넌트만 교체합니다.

---

## 2. CSR (Client-Side Rendering) 흐름

```
1. 브라우저 → index.html 요청 (빈 <div id="root">)
2. 브라우저 → bundle.js 다운로드
3. React 실행 → 컴포넌트 렌더링 → DOM 생성
4. API 호출 → 데이터 받아서 화면 갱신
```

- 검색엔진(SEO)은 JS 실행 전 빈 HTML만 보기 때문에 불리합니다.
- 이 프로젝트는 포트폴리오/로그인 필수 앱이라 SEO 문제가 크지 않습니다.

---

## 3. 브라우저 스토리지 비교

| | localStorage | sessionStorage | Cookie |
|---|---|---|---|
| 유지 기간 | 직접 삭제 전까지 | 탭 닫으면 삭제 | 만료일 지정 가능 |
| 용량 | ~5MB | ~5MB | ~4KB |
| 서버 전송 | 안 됨 | 안 됨 | 자동 전송 |
| JS 접근 | 가능 | 가능 | 가능 (HttpOnly 아니면) |

이 프로젝트에서 `localStorage` 사용 항목:
- `token` — JWT 액세스 토큰
- `ai_persona` — 선택한 AI 페르소나 (`'friend'`, `'mentor'` 등)
- `diary_draft` — 일기 임시저장 (`JSON.stringify({title, content})`)

---

## 4. CORS — 프론트 관점

```
프론트 (localhost:3000) → 백엔드 (localhost:8000)
→ 브라우저: "출처가 다름 → CORS 정책 확인"
→ 백엔드가 Access-Control-Allow-Origin 헤더 없으면 → 요청 차단
```

- 브라우저만 CORS를 체크합니다. Postman, curl은 차단 안 합니다.
- 서버가 `Access-Control-Allow-Origin: *` 헤더를 응답에 포함하면 허용됩니다.
- 프론트 개발자는 CORS 에러가 나면 백엔드에 허용 출처 추가를 요청해야 합니다.
- 이 프로젝트 백엔드는 FastAPI `CORSMiddleware`로 허용합니다.

---

## 5. HTTP 요청 흐름

```
1. 코드: await api.get('/api/diary')
2. axios 인터셉터: Authorization: Bearer <token> 헤더 추가
3. 브라우저: TCP 연결 → HTTP 요청 전송
4. 서버: JWT 검증 → DB 쿼리 → JSON 응답
5. axios 인터셉터: 401이면 토큰 삭제 + /login 이동
6. 컴포넌트: res.data 받아서 setDiaries(res.data)
```

## 6. JWT 토큰 저장 보안 트레이드오프

| 저장 위치 | XSS 위험 | CSRF 위험 | 이 프로젝트 |
|---|---|---|---|
| localStorage | 있음 (JS로 접근 가능) | 없음 | ✅ 사용 중 |
| HttpOnly Cookie | 없음 (JS 접근 불가) | 있음 | ✗ |
| Memory (변수) | 없음 | 없음 | ✗ (새로고침 시 소실) |

- `localStorage`는 XSS 공격 시 토큰 탈취 위험이 있습니다.
- 이 프로젝트는 포트폴리오용이라 localStorage를 사용합니다. 운영 서비스라면 HttpOnly Cookie + CSRF 토큰 조합이 권장됩니다.

## 7. React 렌더링 사이클

```
state/props 변경
    ↓
React: 가상 DOM(Virtual DOM) 새로 계산
    ↓
이전 가상 DOM과 비교 (Diffing/Reconciliation)
    ↓
변경된 부분만 실제 DOM에 업데이트 (Commit)
    ↓
useEffect 실행
```

- 직접 DOM을 조작하지 않고, state를 변경하면 React가 알아서 최소 업데이트를 합니다.
- `key` prop이 없으면 리스트 렌더링 시 어떤 항목이 바뀌었는지 React가 파악하지 못합니다.

```javascript
// key가 있어야 효율적 업데이트 가능
{diaries.map((diary) => <DiaryCard key={diary.id} diary={diary} />)}
```

## 8. SSE vs WebSocket

| | SSE | WebSocket |
|---|---|---|
| 방향 | 서버 → 클라이언트 (단방향) | 양방향 |
| 프로토콜 | HTTP | ws:// |
| 재연결 | 브라우저 자동 재연결 | 직접 구현 |
| 용도 | 알림, 스트리밍 텍스트 | 채팅, 게임 |

이 프로젝트 AI 채팅은 **SSE**입니다. 사용자가 메시지를 보내고(HTTP POST), AI 응답이 스트리밍으로 내려옵니다(서버→클라이언트). 양방향 실시간이 아니라 SSE로 충분합니다.

## 9. XSS (Cross-Site Scripting) 방지

```javascript
// 위험한 코드 — 일기 내용에 <script>alert('XSS')</script>가 있으면 실행됨
element.innerHTML = diary.content;

// 안전한 코드 — HTML 태그를 문자열로 escape
const escapeHtml = (str) =>
  String(str)
    .replace(/&/g, '&amp;')
    .replace(/</g, '&lt;')
    .replace(/>/g, '&gt;')
    .replace(/"/g, '&quot;');
```

이 프로젝트 PDF 내보내기에서 `escapeHtml()`을 사용합니다. React JSX는 기본적으로 자동 escape해서 XSS를 막지만, `dangerouslySetInnerHTML`이나 `Blob` HTML 생성 시에는 직접 처리해야 합니다.

## 10. async/await와 이벤트 루프

```javascript
// JS는 싱글 스레드 — 한 번에 하나만 실행
// 비동기 작업(fetch, setTimeout)은 Web API에 위임하고 메인 스레드는 계속 실행

console.log('1');
setTimeout(() => console.log('3'), 0);  // 0ms여도 이벤트 루프를 거침
console.log('2');
// 출력: 1, 2, 3
```

- `await`는 Promise가 해결될 때까지 해당 `async` 함수만 일시정지합니다.
- 브라우저 UI는 멈추지 않습니다. (메인 스레드는 다른 작업 처리 가능)
- `await` 없이 `fetch()`를 그냥 호출하면 응답을 기다리지 않고 다음 줄을 실행합니다.

## 11. React 컴포넌트 생명주기

```
마운트 (화면에 처음 그려질 때)
  → 함수 실행 → JSX 반환 → DOM 삽입
  → useEffect(fn, []) 실행  ← 데이터 첫 로딩

업데이트 (state/props 변경)
  → 함수 다시 실행 → JSX 반환 → DOM 비교·업데이트
  → useEffect(fn, [의존성]) 실행

언마운트 (화면에서 제거될 때)
  → useEffect cleanup 함수 실행  ← 타이머, 이벤트 리스너 정리
```

이 프로젝트에서:
- `ChatPage` 마운트 → `fetchHistory()` 호출 (대화 내역 로드)
- `messages` 변경 → `scrollIntoView()` 호출 (자동 스크롤)
- `DiaryPage` 언마운트 → `clearTimeout(draftTimerRef.current)` (타이머 정리)

## 12. URL 파라미터와 쿼리스트링

```javascript
// 쿼리스트링: /chat?diary_id=5
const [searchParams] = useSearchParams();
const diaryId = searchParams.get('diary_id');  // "5" (문자열)

// 경로 파라미터: /diary/5
// → Route 설정: <Route path="/diary/:id" />
// → 컴포넌트: const { id } = useParams();

// URL 인코딩 — 한글, 특수문자는 인코딩 필요
const keyword = encodeURIComponent('기쁨 행복');
// → 'keyword=%EA%B8%B0%EC%81%A8%20%ED%96%89%EB%B3%B5'
```

이 프로젝트는 `navigate('/chat?diary_id=3')`으로 일기 ID를 ChatPage에 전달합니다.

## 13. Fetch API vs axios

| | fetch | axios |
|---|---|---|
| 기본 내장 | ✅ (브라우저 내장) | ✗ (설치 필요) |
| JSON 자동 변환 | ✗ (res.json() 필요) | ✅ |
| 인터셉터 | ✗ | ✅ |
| 에러 처리 | 4xx/5xx도 reject 안 함 | 4xx/5xx를 reject |
| 스트리밍 | ✅ (ReadableStream) | ✗ (버퍼링) |

이 프로젝트에서:
- 일반 API → axios (인터셉터로 토큰 자동 추가)
- SSE 스트리밍 → fetch (ReadableStream 필요, axios 사용 불가)

## 14. 환경변수 (REACT_APP_)

```javascript
// .env 파일 (Git에 커밋하면 안 됨)
REACT_APP_API_URL=http://localhost:8000

// 코드에서 사용
const API_URL = process.env.REACT_APP_API_URL || 'http://localhost:8000';
```

- React CRA(Create React App)에서 환경변수는 반드시 `REACT_APP_`으로 시작해야 합니다.
- 빌드 시 번들에 직접 삽입됩니다 → 클라이언트에서 노출됩니다. 비밀키는 절대 넣으면 안 됩니다.
- `.env.local` 파일은 로컬 개발용으로 `.gitignore`에 자동 포함됩니다.
